NovaOptimate JV Pro 2.0

Estoy desarrollando NovaOptimate como un toolkit modular para diagnosticar y optimizar Windows de forma segura. Desde el inicio lo planteé con cambios reversibles y decisiones basadas en el hardware real.

El problema

Quise evitar el enfoque de las herramientas que cambian cosas sin considerar el hardware o sin explicar cómo volver atrás. Por eso diseñé NovaOptimate para analizar primero, separar diagnóstico de modificación y tratar la recuperación como parte del diseño.

Arquitectura modular

Orquestador BAT

Uso el BAT principal para elevar permisos cuando hace falta, validar carpetas, mostrar el menú y despachar cada módulo por archivo.

Diagnóstico PowerShell

En los módulos PowerShell recopilo hardware, red, almacenamiento, drivers, seguridad, batería y estado del sistema usando CIM/WMI y cmdlets nativos.

Seguridad por diseño

  • No incluyo overclock, cambios de voltaje ni modificaciones de BIOS como “optimización”.
  • Integro respaldos, logs y reportes antes de aplicar cambios intensivos.
  • Los perfiles gaming dependen de CPU, RAM, GPU/VRAM, energía, batería, temperaturas y espacio disponible.
  • La copia para terceros se limpia de logs y datos del equipo de desarrollo.

Gaming basado en hardware

En el módulo Gaming mantengo un estado estructurado con datos del equipo y disponibilidad. Si las condiciones reales no son adecuadas, prefiero bloquear un perfil agresivo o marcarlo con precauciones antes que aplicarlo a ciegas.

1 · Elevación y despacho de módulos

El BAT principal valida privilegios y centraliza la ejecución modular.

net session >nul 2>&1
if not "%errorlevel%"=="0" (
  powershell.exe -NoProfile -ExecutionPolicy Bypass ^
    -Command "Start-Process -FilePath '%~f0' -Verb RunAs"
  exit /b
)

:EJECUTAR_MODULO
set "MODULE_FILE=%MODULES%\%~1"
if not exist "%MODULE_FILE%" exit /b 1
call "%MODULE_FILE%"

2 · Estado de evaluación gaming

El motor mantiene datos explícitos y estados “NO EVALUADO” en lugar de inventar información cuando el equipo no la entrega.

param(
  [ValidateSet("Auto", "Gaming", "Competitive", "Streaming", "Profiles")]
  [string]$Mode,
  [string]$LogPath
)

$state = [ordered]@{
  RecommendedProfile       = "NO EVALUADO"
  EquipmentType            = "NO DISPONIBLE"
  RAMInstalledNormalizedGB = 0
  RAMUsableGB              = 0
  RAMAvailableGB           = 0
  DedicatedGPUDetected     = $false
  DedicatedVRAMGB          = 0
  BatteryDetected          = $false
  PowerOnline              = "NO DISPONIBLE"
  Level3Status             = "NO EVALUADO"
}

3 · Diagnóstico de conectividad por capas

Se separan conectividad por IP, HTTPS y resolución DNS para evitar concluir “sin internet” con una sola prueba.

$internetIPResult = Test-NetConnection `
  -ComputerName "1.1.1.1" `
  -InformationLevel Quiet `
  -WarningAction SilentlyContinue

$httpsResult = Test-NetConnection `
  -ComputerName "www.microsoft.com" `
  -Port 443 `
  -InformationLevel Quiet

$addresses = Resolve-DnsName `
  -Name "www.microsoft.com" `
  -Type A -ErrorAction Stop
